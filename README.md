# Vektor RP — канбан-доска команды

Доска для багов GTA 5 RP-сервера: тестеры создают карточки, разработчики берут их в работу,
тестеры проверяют и закрывают. Уведомления — на сайте, в Discord (личка + канал) и в Telegram.

## Что умеет

- Колонки, приоритеты, категории, резолюции и серверы **настраивает администратор** (страница «Настройки»).
- Для каждой колонки: тип (входящие / в работе / проверка / завершение), кто может переносить в неё карточки, лимит задач.
- Карточки: описание, шаги, ожидаемый/фактический результат, координаты, версия сборки, Static ID, время, частота, видео.
- Скриншоты: **Ctrl + V** прямо в форму или в окно карточки (PNG/JPG/GIF/WebP до 5 МБ).
- **Теги** — участники создают их сами прямо в карточке.
- **@упоминания** в описании и комментариях с подсказкой при вводе.
- Подсказка похожих карточек при создании (против дублей), автосохранение черновика.
- Быстрые фильтры: «Мои задачи», «Назначено мне», «Без исполнителя», «Ждёт проверки» + фильтры и поиск.
- Перетаскивание мышью и кнопки переноса в окне карточки (для телефона и клавиатуры).
- Возврат с проверки — только с причиной; счётчик возвратов.
- Комментарии, история изменений, архив, ссылка на карточку `/card/123`.
- Автообновление доски каждые 20 секунд, защита от одновременного редактирования.
- Горячие клавиши: `N` — новая карточка, `/` — поиск, `Esc` — закрыть окно.
- На телефоне колонки переключаются вкладками.

## Роли

| Роль | Может |
|---|---|
| Администратор | всё: пользователи, роли, настройки, архив, удаление |
| Разработчик | создавать карточки, брать себе, переносить (по настройкам колонок), менять приоритет/категорию/теги, комментировать |
| Тестер | создавать и редактировать свои карточки, комментировать, закрывать и возвращать в работу (по настройкам колонок) |
| Ожидает доступа | ничего — так появляется каждый, кто впервые вошёл через Discord, пока админ не выдаст роль |

Права проверяются на сервере. Роль нельзя выбрать самому.

## Запуск на своём компьютере (Windows, PowerShell)

> ⚠️ Команды ниже вводятся **в терминал** (PowerShell в VS Code: `Ctrl + ~`).
> Код из `.py`-файлов в терминал вставлять не нужно.

**1. Создать виртуальное окружение и установить зависимости** (один раз):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**2. Создать файл настроек** `.env` из примера (один раз):

```powershell
Copy-Item .env.example .env
```

Откройте `.env` в VS Code и заполните то, что нужно (всё необязательно для первого запуска).
Секретный ключ генерируется так:

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

**3. Создать первого администратора** (один раз):

```powershell
.\.venv\Scripts\python.exe scripts\create_admin.py
```

**4. Запустить сайт:**

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5000. Остановить сервер — `Ctrl + C` в терминале.

### Если у вас есть база старого прототипа

Скопируйте старый `kanban.db` в папку `instance` (создайте её, если нет) **до первого запуска**:

```powershell
New-Item -ItemType Directory -Force instance
Copy-Item ..\старый-проект\kanban.db instance\kanban.db
```

При запуске приложение само сделает резервную копию в `instance\backups` и добавит новые поля.
Все карточки сохранятся, у них будет «Автор неизвестен».

### Автотесты

Тесты работают на временной базе, ваши данные не трогают:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Вход через Discord

1. https://discord.com/developers/applications → **New Application**.
2. **OAuth2** → скопируйте **Client ID** и **Client Secret** (Reset Secret) в `.env`:
   `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`.
3. **OAuth2 → Redirects** → добавьте `http://127.0.0.1:5000/auth/discord/callback`
   (такой же адрес — в `DISCORD_REDIRECT_URI`). На сервере добавьте второй: `https://ваш-домен/auth/discord/callback`.
4. Перезапустите сайт — на странице входа появится кнопка «Войти через Discord».

Новый пользователь получает статус «Ожидает доступа». Администратор видит его в «Пользователях» и выдаёт роль.

## Discord-бот (уведомления в личку и в канал)

1. В том же приложении → **Bot** → **Reset Token** → токен в `.env` → `DISCORD_BOT_TOKEN`.
2. Пригласите бота на сервер: **OAuth2 → URL Generator** → scope `bot` →
   права *View Channels*, *Send Messages* → откройте ссылку и выберите сервер.
3. ID канала для общих уведомлений: в Discord *Настройки → Расширенные → Режим разработчика*,
   затем ПКМ по каналу → **Копировать ID** → `DISCORD_CHANNEL_ID`.
4. Перезапустите сайт. В консоли появится `[Discord] Бот «…» в сети`.

Личные сообщения приходят, если у пользователя привязан Discord, у него с ботом есть общий сервер
и не запрещены ЛС от участников сервера. Что отправлять в канал, админ выбирает в «Настройки → Общие».

## Telegram-бот

1. В Telegram откройте **@BotFather** → `/newbot` → придумайте имя → скопируйте токен в `.env` → `TELEGRAM_BOT_TOKEN`.
2. Перезапустите сайт. В консоли появится `[Telegram] Бот @… в сети`.
3. Каждый пользователь: **Профиль → «Подключить Telegram»** → в Telegram нажать **Start**. Готово.

Бот работает без публичного адреса (long polling), поэтому подходит и для локального ПК.
Один токен должен работать только в одном месте: если бот запущен и на ПК, и на VDS, один из них будет ждать.

## Структура

```
app.py                  запуск для разработки (127.0.0.1:5000)
serve.py                запуск на сервере через Waitress
requirements.txt        зависимости: Flask, Waitress, python-dotenv
.env.example            пример настроек (копируется в .env)
vektor/                 код сервера
  __init__.py           сборка приложения, заголовки безопасности
  db.py                 база, миграции, резервные копии
  auth.py               вход, сессии, CSRF, защита от перебора
  api.py                API карточек, комментариев, вложений, профиля
  admin.py              API администратора
  pages.py              HTML-страницы
  permissions.py        правила доступа
  notify.py             уведомления
  discord_api.py        Discord: OAuth и бот
  telegram_bot.py       Telegram-бот
templates/              HTML-шаблоны
static/                 CSS и JavaScript
scripts/                create_admin.py, backup_db.py
tests/                  автотесты
instance/               база, загрузки, копии (не попадает в git)
```

Перенос на VDS с Windows Server — в [DEPLOY.md](DEPLOY.md).
